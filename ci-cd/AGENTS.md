# AGENTS.md — Hospital DR: 실행 우선 개발 규칙

> 적용 대상: 이 저장소에서 작업하는 모든 Codex/AI 에이전트.
> 최우선 목표: **기존 AWS DR 인프라에서 실제로 작동하는지 확인**한다.
> 이 문서는 이전 개발 제안, 과거 세션의 부가 목표, 선택적 설계 문서보다 현재 작업 범위에 대해 우선한다. 사용자 최신 지시가 있으면 그 지시를 따른다.

## 1. 목표 — 오직 세 가지, 순서 고정

1. **FAILOVER**: 기존 AWS DR Web/EMR/DB를 이용해 Failover가 실제 실행되는지 검증한다. 실행 로그뿐 아니라 기존 DR 서비스의 기동, Health, 필요한 서비스 접근 결과로 판단한다. 사용자에게 보이는 웹 전환을 검사할 때는 **`hospital-web.pp.ua`**를 사용한다.
2. **NR / CDC**: 실제 원본 MySQL과 기존 AWS DR MySQL 간 Position/Binlog 복제가 연결되는지, 원본의 실제 변경 데이터가 DR MySQL에 적용되는지 검증한다. 수신 위치와 *실제 적용 위치*를 구분한다.
3. **DUMP**: 기존 Dump 파일을 검증·복호화·복원해, **기존 AWS DR MySQL**에 실제 데이터가 반영되는지 검증한다. 기존 DR 데이터를 손상시키지 않도록 대상 스키마/복원 방식과 변경 범위를 먼저 확인한다.

**현재 범위는 위 세 검증뿐이며, 아래 순서대로 진행한다.** 요청에 없는 Failback, 신규 인프라(합성 서버 포함), 신규 인증서, 테스트 도메인, 부가 기능, 모니터링 고도화 등으로 범위를 넓히지 않는다. 위 세 범위 밖의 작업은 사용자가 명시적으로 요청한 뒤에만 시작한다.

## 2. 인프라·비용·보안·자격증명 보호 절대 규칙

- **기존 AWS DR 인프라만 사용한다.** 먼저 AWS 실측으로 기존 Web/EMR/DB 인스턴스 ID와 역할을 식별한다. 이름이나 과거 문서로 추정하지 않는다.
- **명시적 사용자 승인 없이 새 EC2, RDS, EIP/공인 IPv4, NAT Gateway, VPC, Subnet, VPC Endpoint, Load Balancer, KMS 키, 유료 리소스를 생성하지 않는다.** Terraform `apply` 등으로 간접 생성하는 것도 포함한다. 단기간 테스트·저비용·무료라는 이유로 예외를 만들지 않는다.
- **기존 리소스·데이터를 임의 삭제하거나 Terraform destroy를 실행하지 않는다.** 추가된 합성/Probe 자원은 비용·의존성을 파악한 뒤 정리 후보로만 보고한다. 삭제에는 별도 승인이 필요하다.
- **`hospital-web.pp.ua` 외의 임시 테스트 도메인, Cloudflare CSR/Origin 인증서 발급, 별도 DNS 우회 경로를 새로 만들지 않는다.** 실제 도메인 전환이 필요한 경우 기존 레코드 백업·롤백 준비 후 사용자 승인을 받는다.
- AWS 테스트가 끝나면 **테스트 때문에 켠 인스턴스만** 원래 상태로 복구한다. 계속 켜둬야 하는 경우 비용·이유를 보고한다. EC2 `stopped`가 무과금을 의미하지 않는다는 점을 고려한다.
- 프로젝트 AWS 예산 상한은 약 **5만 원**으로 간주하며, 신규 비용이 생기는 제안은 예상 비용·기존 자원으로 불가능한 이유를 설명하고 승인 전에는 실행하지 않는다.
- 비밀번호, API 토큰, 세션 시크릿, 암호화 키, 개인키, 덤프 내용 등 비밀정보를 저장소에 넣거나 터미널 출력, 로그, 증거 파일, 커밋에 노출하지 않는다. 이미 노출된 값도 응답이나 보고서에 다시 복사하지 않는다.
- 자격증명은 기존 외부 시크릿 저장소와 기존 AWS 자격증명 체인만 사용한다. 비밀값을 명령행 인자에 넣거나 사용자에게 채팅으로 붙여넣도록 요청하지 않는다. 필요한 실행은 기존 런타임 메커니즘으로 대상 프로세스에 전달하고 값을 출력하지 않는다.
- 시크릿 파일이나 개인키의 값은 점검 목적으로 열람·복사하지 않는다. 필요한 환경변수 이름, 파일 존재 여부, 소유자·권한 등 메타데이터만 확인한다. 개인키는 Git 밖에 두고 기존 제한 권한(예: `0600` 또는 `0400`)을 유지하며, 백업·임시 복사본을 만들지 않는다.
- 자격증명 발급·회전·폐기, 시크릿 저장 위치 변경, IAM 권한·승인 게이트 완화는 사용자 명시 승인 없이 하지 않는다. 필요한 값이 없으면 필요한 변수 이름과 차단 원인만 보고한다.

## 3. 실제 실행 우선 원칙

- 코드 단위 테스트, 모의 DB, SQLite, 신규 합성 EC2에서의 PASS는 **실제 DR PASS가 아니다**. 결과를 섞거나 성공으로 포장하지 않는다.
- 기존 구현을 재사용하고 **현재 목표를 막는 직접 원인만 최소 수정**한다. 기존에 PASS한 검증을 무의미하게 반복하지 않는다.
- 승인 가능한 범위 내에서 기존 인스턴스 시작/중지, 읽기 전용 점검, 코드 수정 및 비파괴적 Health 검증은 자율 진행한다. 운영 DNS 변경, 실제 운영 DB 덮어쓰기·쓰기 전환, 승인 정책 완화, 리소스 생성/삭제는 명시적 승인 전 실행하지 않는다.
- 원본 On-Prem 서버가 현재 없으면 이를 네트워크 장애로 오진하지 않는다. **NR 실연결이 불가능하면 `BLOCKED_SOURCE_UNAVAILABLE`로 사실대로 보고**하고, 사용자 허락 없이 대체 서버를 만들지 않는다.
- 장애 시 원본 DB 접속 불가는 자연스러울 수 있다. RPO 측정 불가와 복구 원본 부재를 구분하되, **운영 승인·데이터 보호 장치를 임의 우회하지 않는다**. 필요한 정책 변경은 실행 대상과 위험을 구분하여 사용자에게 묻는다.
- 1인 시연 승인을 운영 일반 Failover의 2인 승인으로 가장하지 않는다.
- 작업이 막히면 같은 진단과 보완 요구를 반복하지 말고 **실제 차단 원인 1개와 가장 작은 해결 조치**를 보고한다. 사용자가 지시하지 않은 우회 인프라를 만들지 않는다.

## 4. 작업 순서 및 결과 보고

1. 현재 AWS 인스턴스·DB·DNS·비용 발생 자원 현황을 **한 번만 읽기 전용으로** 식별한다. 기존 DR 3대와 추가 테스트 자원을 구분한다.
2. **FAILOVER**를 기존 DR 경로에서 우선 실제 실행·검증한다. 불가능하면 하나의 차단 원인과 필요한 최소 조치만 보고한다.
3. 다음에 **NR(CDC)** 실제 연결·데이터 적용을 확인한다. 원본 서버가 없으면 BLOCKED로 남기고 임의 합성 성공으로 대체하지 않는다.
4. 이어서 **DUMP** 기존 백업의 실제 DR DB 복원을 확인한다. 무결성·복원 가능성과 RPO 목표 달성은 서로 다른 결과로 기록한다.
5. 새 기능·추가 검증·아키텍처 변경은 위 세 가지가 끝난 뒤 사용자가 명시적으로 요청할 때만 수행한다.

매 보고는 다음 형식으로 짧게 작성한다.

```text
FAILOVER: PASS / FAIL / BLOCKED / NOT_TESTED — 실제 대상 및 증거
NR_CDC: PASS / FAIL / BLOCKED / NOT_TESTED — 적용된 데이터와 위치 또는 차단 원인
DUMP: PASS / FAIL / BLOCKED / NOT_TESTED — 실제 DR 복원 결과 또는 차단 원인
AWS_RESOURCES: 기존 DR 수 / 추가 자원 수 / 새로 생성한 자원 0개
COST_CHANGE: 없음 / 금액·근거
NEXT_ACTION: 가장 작은 후속 작업 한 가지
```

**완료의 기준은 '더 정교해진 코드'가 아니라, 사용자가 요청한 세 기능의 실제 DR 동작이다.**
